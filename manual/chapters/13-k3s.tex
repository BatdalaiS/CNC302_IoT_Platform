\subsection{2.2 {[}Pi{]} Pi 3B --- товлогчийн (scheduler) харах тоо}\label{pi-pi-3b-ux442ux43eux432ux43bux43eux433ux447ux438ux439ux43d-scheduler-ux445ux430ux440ux430ux445-ux442ux43eux43e}}

Товлогч бодит RSS-ийг биш, зангилааны \textbf{Allocatable} ба pod-уудын \textbf{\texttt{requests}}-ийн нийлбэрийг харьцуулна (\href{https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/}{Resource Management}). \texttt{Allocatable\ =\allowbreak{}\ Capacity\ −\ kube-reserved\ −\ system-reserved\ −\ eviction-hard} (\href{https://kubernetes.io/docs/tasks/administer-cluster/reserve-compute-resources/}{Reserve Compute Resources}). K3s-ийн kubelet-д \textbf{reserved тавиагүй}, hard eviction нь зөвхөн дискний (\texttt{imagefs.\allowbreak{}available\textless{}5\%,nodefs.\allowbreak{}available\textless{}5\%}) --- санах ойн босго \textbf{байхгүй} (\href{https://docs.k3s.io/security/self-assessment-1.12}{CIS 1.\allowbreak{}12 Self-Assessment}-ийн kubelet тохиргоо). Тиймээс:

Өөрийн Pi дээр шалга (CIS хуудасны audit командтай ижил):

\begin{verbatim}
Allocatable (Pi) ≈ Capacity ≈ 925 Mi       ← kubectl describe node <pi>-ээр БАТАЛ
requests: mosquitto 32 + edge-agent 96 × N
  N = 1 → 128 Mi    N = 3 → 320 Mi    N = 8 → 800 Mi    N = 9 → 896 Mi
\end{verbatim}

\textbf{Гол зөрчил:} товлогчийн хувьд N ≈ 9 хүртэл "багтана", гэтэл бодит сул санах ой (\textasciitilde545 MiB) \textasciitilde110 MiB-ийн агентыг \textbf{4--5}-аас илүү даахгүй. Товлогч k3s agent ба OS-ийн \textasciitilde380 MiB-ийг \textbf{мэдэхгүй} --- reserved тавиагүй учраас. Үр дүн нь \texttt{Pending} \textbf{биш}, харин цөмийн OOM killer (\texttt{OOMKilled}, Exit 137) эсвэл swap дээр мөлхөх. Pi-д 2 GB swap бий (SETUP Б.5): Kubernetes-ийн анхдагч \texttt{NoSwap} горимд \textbf{pod-ууд swap ашиглахгүй}, харин k3s agent зэрэг systemd үйлчилгээ ашиглаж чадна (\href{https://kubernetes.io/docs/concepts/cluster-administration/swap-memory-management/}{Swap memory management}) --- зангилаа удаашрах боловч амьд үлдэж магадгүй. \texttt{requests} бол \textbf{амлалт}, \texttt{limits} бол \textbf{хана}, \textbf{RSS бол үнэн} --- гурвыг нь \texttt{kubectl\ top} + \texttt{free\ -m}-ээр зэрэг хэмжиж тайландаа бич.

\begin{quote}
\textbf{coredns / metrics-server / local-path-provisioner} хаана байна? Тэд nodeSelector-гүй тул товлогч аль ч зангилаанд тавьж болно. \texttt{kubectl\ get\ pods\ -A\ -o\ wide}-аар шалга. Pi дээр буусан бол тэдний санах ойг Pi-гийн төсөвт нэм.
\end{quote}

\textbf{\texttt{requests} ба \texttt{limits}-ийн ялгаа чухал:} \emph{"the scheduler ensures that, for each resource type, the sum of the resource requests of the scheduled containers is less than the capacity of the node"}; санах ойн limit давбал \emph{"the Linux kernel out-of-memory subsystem activates"} (\href{https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/}{Resource Management}).
